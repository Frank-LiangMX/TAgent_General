> **日期**：2026-07-24

## 0. 总体规划

### 0.1 时间线

```
1.7 版本（重构前最后一个）
├── 稳定版本，bug 修复
├── 不加新功能
└── 作为"告别版"

2.0 版本（两周内）
├── 全切 Pi Agent
├── kscc 用 KsccBareProvider
├── Xfast 模式
├── 材质精简
├── Assistant 回复行为优化
├── 长会话 UI 优化
└── 全新架构
```

### 0.2 架构变更

```
1.x 架构：
├── Claude Agent SDK（单核）
├── kscc 完整 Agent（resume 模式）
└── Proma 信息流行为

2.0 架构：
├── Pi Agent（唯一 runtime）
├── kscc bare（KsccBareProvider，模型泵）
├── Xfast 模式（竞争调度）
├── 自研信息流行为
└── 分页懒加载 + minimap + 刻度条
```

### 0.3 与 Proma 分道

**不借鉴**（自研）：
- ❌ Skill 系统（TAgent 自研）
- ❌ 记忆系统（TAgent 自研）
- ❌ Proactive 主动系统（优先级低）

**借鉴**（Proma → TAgent）：
- ✅ 双 Runtime 适配层（但 TAgent 不需要双 Runtime，只借鉴模式）
- ✅ EventBus 解耦模式
- ✅ Pi Agent 稳定性修复

## 3. 关键决策记录

### 3.1 Xfast 模式

**决策**：竞争调度，高峰期自动选最快模型

**机制**：
- 首轮竞争（3 模型）
- 心跳检测（每 5 分钟）
- 定期刷新（每 10 轮）

**量化**：
- 高峰期快 2-4 倍
- token 消耗约 1.2-1.5×/轮

**文档**：`docs/plans/2026-07-24-xfast-mode-design.md`

### 3.2 材质精简

**决策**：保留所有 ThemeStyle，删除 AdvancedMaterialMode

**删除**：
- ❌ AdvancedMaterialMode（glass, frosted, soft）
- ❌ `[data-material]` 相关样式
- ❌ 设置页中的高级材质选择器

**影响**：436 处引用需要清理

**文档**：`docs/plans/2026-07-24-xfast-mode-design.md` §10

### 3.3 Assistant 回复行为

**决策**：借鉴 Kun，优化 assistant 回复行为

**改动**：
- 推理过程折叠（思考 + 工具调用放入折叠区）
- 最终答案独立（只有最后一个 assistant block 显示为答案）
- 文件引用链接（assistant 可引用本地文件，用户可预览/打开）

**工作量**：2 天

**文档**：`docs/plans/2026-07-24-assistant-reply-behavior.md`

### 3.4 长会话 UI 优化

**决策**：借鉴 Kun，分页懒加载 + minimap + 刻度条

**改动**：
- 分页懒加载（每次渲染 18 个 turn）
- 折叠旧历史（显示"显示更早的 N 条消息"按钮）
- minimap 适配（完整历史缩略图，点击跳转）
- 刻度条适配（完整历史，点击跳转）

**工作量**：3-4 天

**文档**：`docs/plans/2026-07-24-long-session-ui-optimization.md`

### 3.5 Pi Agent 迁移

**决策**：两周内全切 Pi Agent，不需要双 Runtime

**架构**：
- Pi Agent 唯一 runtime
- kscc bare 是模型泵（KsccBareProvider）
- 不是退路，而是模型来源

**借鉴**（Proma）：
- ✅ 双 Runtime 适配层模式
- ✅ EventBus 解耦模式
- ✅ Pi Agent 稳定性修复

**文档**：`docs/plans/2026-07-18-agent-runtime-dual-core-pi-migration.md`
